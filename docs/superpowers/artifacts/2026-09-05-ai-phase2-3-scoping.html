AI across Docs, Tasks, Calendar & Contacts

Mail already has the full AI stack: a locked self-hosted model, streaming with citations, injection scrubbing, an embeddings pipeline (bge-m3 + pgvector), a commitments extractor, and now a shared working indicator. Everything below reuses that plumbing — nothing needs new infrastructure.

Docs

IdeaEffortWhat it is
Writing assistantS–MRewrite / adjust tone / summarize the selection inside the TipTap editor — a direct port of mail's rewrite tasks into DocsEditor's bubble menu. The quickest win in the whole list.
Draft from threadM"Turn this email thread into a memo / minutes" — picks a gov template, fills it from the thread, opens in Docs. Bridges the two modules and shows off the template system.
Ask this documentMDoc-scoped Q&A with cited passages. Needs a doc_embeddings table — the message-embeddings worker generalizes to a source-typed embeddings pipeline.
Minutes formatterSPaste raw notes into the Meeting Minutes template → structured attendees / decisions / action items.

Tasks

IdeaEffortWhat it is
Thread → tasksSThe commitments extractor already finds action items in mail — add "create task" one click away, prefilled with title, source link, and deadline. Highest value-to-effort in this document.
Natural-language entryS"Remind me Friday to chase the TOR" → parsed into title + due date + priority in the task composer.
Workload digestSThe morning briefing gains a section joining open tasks and commitments — extends an existing panel rather than adding UI.

Calendar

IdeaEffortWhat it is
Smart event from mailMDrag-mail-to-calendar already exists — AI prefills title, time, location, and attendees from the email body instead of leaving a blank form.
NL event creationS"Steering committee Tuesday 10–11 with Erick and Tricia" → parsed event.
Meeting prep packM–LBefore each meeting: a brief built from related threads, docs, and open commitments with the attendees — the flagship "staff of three" feature, built on cross-module embeddings.

Contacts

IdeaEffortWhat it is
Relationship dossierMOpen a contact → recent interactions, open commitments both ways, waiting-on status. The data all exists; this is retrieval + one summarization call.

Cross-cutting decisions to make once

  • One Ask, wider scope: should "Ask your inbox" grow into "Ask 1Gov" (mail + docs + calendar), or stay per-module? Recommendation: one entry point, source-typed citations — the intelligence rail is already the home for it.
  • Generalize the embeddings pipeline: message_embeddings → a source-typed table (source: mail|doc), one worker. Prerequisite for doc Q&A and meeting prep.
  • Guardrails travel with the stack: injection scrubbing, mandatory citations, and the suspicious-content flag apply to every module from day one — they're already library code.
  • Model policy: the new NEXT_PUBLIC_AI_MODEL lock governs all modules automatically; nothing new needed.
