The finish pass: closing the gap between 1Gov Mail and the references

Direction agreed in session: email-native polish (reference image 3 as base), with inline reply, the icon rail, and attachment cards in scope. The codebase audit changed the shape of the work — here's the revised proposal.

4 September 2026 · based on an audit of apps/web on branch ft-hyperscale

The verdict: you already built the features. What's missing is the finish.

All three scoped items exist today — an inline reply bar, a collapsible 60px icon rail, and typed attachment tiles. The visual gap between 1Gov Mail and the reference designs comes almost entirely from consistency debt: ~110 ad-hoc Tailwind colors bypassing the state-blue token system, a private type scale of magic rem values, muted text at ten different opacity levels, and hand-rolled buttons where shadcn primitives exist. The references look polished because they speak one visual language everywhere. The single highest-impact change is a consistency pass, not any new component.

Proposed workstreams

A · Consistency foundation

Priority 1 M–L

The pass that makes everything else read as designed. One palette, one type scale, one component language — applied mechanically across the mail surfaces.

  • Tokens only. Replace raw palette classes (bg-blue-500/10, text-amber-700, blue-400 status pills) with the existing token system. Biggest offenders: AttachmentTile.tsx (~40), ThreadView.tsx, ThreadMessage.tsx, MailList.tsx, ThreadHeader.tsx.
  • Name the type scale. The magic sizes (text-[0.719rem] and friends) become five named steps in globals.css — sizes paired with weight, tracking, and line-height, so the Inter-done-right look of reference 3 is encoded, not approximated:
StepSizeWeightTrackingUsed for
display1.375rem700−0.02emPane headings, empty states — Inter wants negative tracking at this size
title0.9375rem600−0.01emThread subject, dialog titles
body0.875rem400 / 6000Message bodies, compose, list sender (600)
ui0.8125rem400 / 5000List subject + snippet, buttons, inputs, chips — subject vs snippet differ by weight, not a 1px size step
micro0.6875rem500 / 600+0.06em upperSection headers, badges, timestamps (tabular-nums)
  • Three tiers of muted, not ten. Collapse the opacity soup into secondary / tertiary / faint text tokens and border strong / default / faint.
  • Adopt the primitives. Swap raw <button> elements in the mail views for Button variants; use Badge for pills; replace the hand-rolled row checkbox and sidebar context menu with the ui/ components.
  • One avatar. Fold the three initials implementations into MailAvatar, resolving the colored-circles vs neutral contradiction (neutral wins — it's the documented intent).
  • Fix the two real bugs: hsl(var(--x)) wrapped around oklch variables in globals.css (ProseMirror blockquote/code) and ComposeModal.tsx:1171 — those colors silently fail today.

B · Inline reply, upgraded to a mini-composer

Priority 2 M
Today QuickReplyBar.tsx: plain textarea, expands to 3 rows, ⌘↵ send, "open full editor" link.
Reference A real composer docked in the thread: recipient chips, formatting toolbar, expand control, Send button with presence.
  • Recipient chips (To, with reply/reply-all switch) so it's clear who receives the reply before sending.
  • Compact formatting toolbar — bold, italic, list, link — appearing when the bar is focused/expanded. Reuse the existing TipTap setup rather than a second editor.
  • Attachment and emoji affordances, a proper primary Send button, and the expand-to-full-compose control kept as the escape hatch into ComposeModal.
  • Visual weight: card surface, hairline border, subtle shadow — it should read as "the reply lives here," not a search box.

C · Icon rail polish

Priority 2 S
Today Sidebar.tsx collapses 220px → 60px, persisted. Colored icon chips carry over; no badges or tooltips when collapsed.
Reference Slim rail with tooltips, an unread count badge on Inbox, quiet monochrome icons, theme toggle at the foot.
  • Unread badge on the collapsed Inbox icon (and a dot on folders with unread).
  • Tooltips on every rail item using the existing ui/tooltip.
  • Rail aesthetic: swap the colored icon chips for quiet monochrome icons with the active item picked out in primary — color returns in the expanded state if you want to keep the chips there.
  • Fix the tablet gap: sidebar currently appears only at lg while the reader splits at md — show the rail from md so there's always navigation.

D · Attachment cards, completed

Priority 3 S
Today AttachmentTile.tsx: 100×112 typed tiles, thumbnails, hover preview/download. No file size, no bulk action.
Reference Cards with type icon, name, size, and a "Download All" link on the attachment strip.
  • Show file size on each tile.
  • "Download All" action on message attachment strips and the thread Attachments tab (zip on the API, or sequential downloads as the cheap first version — decide at implementation).
  • Tile colors move onto tokens as part of workstream A.

Sequencing & effort

OrderWorkstreamEffortWhy this order
1A · Consistency foundationM–LEverything after it lands on clean tokens instead of adding to the debt. Includes the two silent color bugs.
2C · Icon rail polishSSmall, self-contained, immediately visible; also fixes the tablet nav gap.
3D · Attachment cardsSTwo additive changes to an already-good component.
4B · Mini-composerMThe largest UX change; benefits from the primitives and tokens being settled first.

Explicitly out of scope

  • Message list redesign — deselected in session. The list already has avatars, time grouping, and filter tabs; row colors get touched only via workstream A.
  • Productivity-inbox restructure (reference image 2's Activity-feed model) — different product, not this pass.
  • Pane resizing / layout re-architecture — noted in the audit (fixed 300px list), parked unless you pull it in.
  • The two parallel readers (ThreadView + MailDetail fallback, ~87 KB combined with duplicated email-CSS constants) — a real consolidation candidate, but it's refactoring, not look-and-feel. Flagged for a future pass.

Palette staying exactly as it is

The token system is good — state blue with the Rwanda accent on a warm off-white ground. This proposal enforces it; nothing about the palette itself changes.

Decisions — resolved 4 Sep 2026

  • Scope of workstream A: mail surfaces first, but token names, type steps, and muted tiers are designed app-wide so settings/docs/calendar adopt them later without rework.
  • Mini-composer: inline becomes the default reply path — Reply/Reply-all in the thread focus the inline composer; the modal is reached via expand.
  • Download All: cheap sequential downloads now; a zip endpoint is future API work.
