AI Personalization

Profile-contextualized prompts in three phases: account-level instructions, a structured identity card, and a derived writing-style card — always tiered, because on a 16k-context local model every profile token trades against history, tool results, and the anti-fabrication mandates.

P1 · Account-level instructions + identity ship first — small

The gap today isn't missing context — it's that the personalization you already built lives on the wrong side: custom instructions sit in device-local storage and reach only client-side tasks. P1 moves them to the account and threads them server-side.

  • New user_ai_profiles table (one migration carries P1+P2 fields: instructions ≤500, jobTitle/institution/department ≤80, language) — hand-authored per the repo workflow.
  • GET/PATCH /settings/ai-profile; DTO enforces the caps.
  • One shared buildProfileBlock() in packages/shared — neutralized, capped, explicitly subordinated to the hard rules, rendered identically everywhere it's consumed.
  • Web auto-migrates the localStorage instructions to the account once, then reads through.
  • Settings gains a Profile panel OUTSIDE the AI section — so it survives builds that lock NEXT_PUBLIC_AI_MODEL and hide the AI section (.155).

P2 · Structured identity card + seeding rides with P1

  • Profile: <title>, <department>, <institution>. Preferred language: <lang>. — a short structured card beats a longer free-text blob on small models.
  • Seeded, not typed: GET /settings/ai-profile/suggestions derives candidates from the Zimbra identity and a GAL self-lookup; the user confirms chips, nothing saves silently.
  • Card additionally reaches suggestReply/rewrite and meeting prep (output that speaks as the user).

P3 · Derived writing-style card own plan, later

  • Weekly cron (6th worker) distills ~40 recent Sent messages into a descriptive JSON card (formality, length, greetings/sign-offs, language mix) stored as ai_generations kind style_profile. ~30 generations/hour at full 5,000-mailbox scale — noise on the GPU pool.
  • Consumed only by suggestReply, rewrite, and the agent's drafting guidance (capped ~300 chars).
  • Why it's separate: the card is distilled from email content — an injection surviving distillation would land in a system prompt. Mandatory: fenced distillation, schema validation, detectInjectionAttempt scan (tombstone on suspicion), descriptive-only rendering — never raw quoted sentences.

Why tiered is non-negotiable: the agent runs a 16k context with a 35k-char transcript cap because Ollama truncates oldest-first and drops the security mandates, and long context is qwen3's fabrication trigger — we already trimmed history to 6 turns for exactly this. Injection cost is otherwise trivial (~100 tokens ≈ <70 ms prefill at measured rates).

Out of scope

Admin-managed org directory (admin-console stream) · profiles of other users (dossiers cover counterparties) · personalizing summaries/cards/embeddings · multi-language UI.
