02 · Eliminated

Mechanisms checked and cleared.

  • A DateTimePicker feedback loop. There isn't one. It is a Popover plus a Button, not a native datetime-local input, and it only calls onChange from two user-gesture handlers inside the closed popover. Nothing fires during render, and the bare-date ↔ datetime flip is absorbed by its isValid guard.
  • Radix Checkbox re-emitting a click. A real ping-pong shape — CheckboxBubbleInput dispatches a bubbling click whenever checked changes programmatically — but that input only mounts when the control sits inside a <form>. The modal is plain divs. Confirmed in the installed source and in the browser.
  • window.history.replaceState under Next's patched history. Reproduced through router.push in a production build: one mount, one fill.
  • Non-React CPU sinks. repairTruncatedJson strictly decreases and terminates; findFreeSlots is bounded by maxSlots; both LRU while loops break on an empty key; AIClient.chat is non-streaming.
  • A stale bundle. I pulled the deployed chunk off 10.10.94.154:3000 and diffed the minified modal and validate() against HEAD — identical, ece1504 fix wave included.
  • A silent React update loop. Inconsistent with "no console errors": React throws Maximum update depth exceeded for effect loops and Too many re-renders for render-phase ones. A silent peg points somewhere else.

03 · Findings

What was actually broken.

A

The write-back could never be a no-op

mergeParsedEvent always returned a fresh attendees array whenever the parse carried at least one attendee — even when nothing was added. The modal guarded on identity, so the guard was never false and every fill run committed a state update.

// page.tsx:408 (before)
if (merged.attendees !== current.attendees) setAttendees([...merged.attendees]);

With the effect observed running twice in the field, this is the one hop of the suspected cycle that is real and provable: a repeated fill rewrote form state rather than settling — exactly the amplifier a remount cycle needs to sustain itself.

Fix — keep the current reference when nothing was added, and compare by value at the call site. A repeated merge is now a fixed point: the second run calls no setter at all.

B

An all-day fill put a bare date into form state

All-day parses keep bare dates by design, and the {startAt: null, endAt: "…"} shape escapes repair entirely, so startAt could hold either "2026-09-12" or "2026-09-12T09:00" depending on the parse. Two readers then disagree: new Date("2026-09-12") is UTC midnight, while everything else treats the string as local. Uncheck All-day and the save path shifts the event by the local offset — Kigali is +2. Confirmed live in the browser.

Fix — toFormDateTime widens a bare date at the merge boundary (T00:00 for start, T23:59 for end), so form state carries exactly one shape. Both all-day consumers still split on T and are unchanged.

C

The mirror ref was written during render

The final-review flag was worth acting on. currentRef.current = {…} ran in the render body, so an abandoned concurrent render could leave the mirror holding values the form never committed — which the async fill would then merge against. Moved to a post-commit effect. It schedules nothing, so it never participated in a loop, but it is a genuine correctness hazard on this exact path.

Contracts preserved: dirty fields still never overwritten · no auto-save · abort semantics on unmount and Save untouched.

The double effect run is also still unexplained: the deps are a string and a boolean, so it implies a remount, yet a production build entered by router.push mounts once. I left it alone on purpose — a "fill only once" guard would make a remount worse, since the remount resets the form and the guard would then refuse to refill it. After finding A it costs a wasted request, not a state change.
