Strengths

What this plan got right, judged across the whole range rather than task by task.

  • The extraction paid for itself immediately. Pulling textToHtml out of ComposeModal surfaced a real self-escaping bug — the old order emitted <br/> then escaped its own <, so every single newline in a rewrite rendered as literal &lt;br/> text. One helper, one test file, one behaviour fix, three call sites.
  • The fallback contract is genuinely deterministic. parseTaskInput wraps everything — the fetch, the JSON salvage, the field validation — in a single try/catch returning fallbackParse(input). The feature cannot block task creation, and both call sites inherit that for free.
  • The promote extension is backward-compatible in the direction that matters. Empty body preserves the derived title/description exactly, the saga compensation and double-promote guard are untouched, and the new API spec test asserts both the override merge and the empty-body default in one case.
  • The payload contract holds end to end. TaskModal builds a nine-field payload; the mail page plucks exactly the four the DTO declares. Nothing leaks — and even if it did, the API's ValidationPipe runs whitelist: true without forbidNonWhitelisted, so extras are stripped rather than 400'd. form.dueDate is YYYY-MM-DD or undefined, never '', so @IsDateString() never sees an empty string.
  • Decision C was the right call and is verifiably exact. The workload strip's overdue rule (dueDate < local midnight) is character-for-character the rule formatDueDate and isOverdue already use on the tasks page, so the strip and /tasks can't disagree. ['tasks','workload'] sits under the ['tasks'] prefix — invalidation reaches it, no collision with GlobalSearch.
  • Docs collab discipline was respected. No setContent anywhere; ranged inserts only. Both DocsEditor mounts are keyed by doc id, so the unmount abort effect fires on every doc switch — no listener or in-flight request survives a switch.
  • The build-script fix carries its own postmortem. The in-bundle prisma generate comment explains why the workspace generate isn't enough and names the exact crash it prevents. That comment is worth more than the three lines it guards.
  • Tests assert behaviour, not mocks. The quick-add tests drive the real parseTaskInput through a fake chat; the TaskModal test drives the real modal and asserts the rendered form. No mocks-of-mocks anywhere in the new suite.

Issues

Nine findings. Severity reflects blast radius, not effort.

Critical — must fix

None. No data loss, no auth gap, no injection path. Every model output that reaches the DOM goes through textToHtml, which escapes < before any tag can open.

Important — should fix

I1The docs AI range is an unmapped position snapshot held across the whole model call

runAi snapshots {from, to} and applyAi uses those absolute positions verbatim, seconds later. The editor stays fully editable while the preview streams, and the doc is collaborative — so a local keystroke or a remote peer typing above the selection shifts every position after it. Apply then replaces the wrong span. Worse, if the doc shrank below aiRange.to, insertContentAt throws a ProseMirror range error straight out of the click handler.

Fix: clamp both ends to editor.state.doc.content.size before applying, and either map the range through the transactions since the snapshot or close the popover on the first non-AI update event. The clamp alone removes the throw.

apps/web/components/docs/DocsEditor.tsx — runAi / applyAi
I2"Insert below" splits the paragraph when the selection ends mid-block

Summarize inserts a <p> at aiRange.to. When that position sits inside a paragraph — the normal case for selecting a sentence — TipTap splits the paragraph in two and drops the summary between the halves. Decision B says the summary lands below the selected prose, not through it.

Fix: insert at the parent block boundary, editor.state.doc.resolve(to).after(), rather than the raw selection end.

apps/web/components/docs/DocsEditor.tsx — applyAi
I3Two of the four features skip the abort guardrail the other honours

The spec's cross-cutting rule is that every AI call is abortable. DocsEditor does it properly — controller per run, predecessor aborted, cleanup on unmount. Neither the tasks quick-add nor the mail page's due-hint parse passes a signal at all, so a hung local model leaves the Add button and the commitment row spinning with no way out but a reload. Both already accept opts.signal; the wiring is the only thing missing.

Fix: an AbortController ref in each caller, aborted on unmount and on a second submit. The deterministic fallback then converts a cancel into a plain task rather than a hang.

Minor — nice to have

M1The AI indicator shows while AI is switched off

Quick-add renders AIWorkingIndicator step="Parsing your task" on quickAdding alone. With AI disabled no model is called, yet the user watches a pulsing spark claim otherwise. Gate it on quickAdding && aiEnabled.

M2The parser's reference date is UTC while the rest of the app is local

parseTaskInput derives "today" from toISOString().slice(0,10) and getUTCDay(). In Kigali (UTC+2) that means between midnight and 02:00 local the model is told the wrong date and the wrong weekday, so "tomorrow" and "Friday" resolve one day early. Use local date parts, matching the toast's own parseISO-then-format handling.

M3The workload strip renders an empty labelled box on error

The spec says render nothing when the query fails. The bordered card and its "Your workload" eyebrow render unconditionally on expanded; only the two lines inside are guarded, so a failed fetch with no commitments count leaves a titled empty box. Guard the wrapper on having at least one line.

M4Clearing the description silently restores the server's derived text

TaskModal sends form.description || undefined, so a deliberately emptied field is omitted and the service's ?? falls back to "Due hint: … Extracted from email." The user clears a field and the text comes back. Same shape for title, where ?.trim() || falls back to the commitment text.

M5Promote success doesn't invalidate the tasks queries

onSaved invalidates ['commitments'] only. The new workload strip and GlobalSearch both read ['tasks'] and stay stale for up to their 60s window after a task is created from a commitment. One extra invalidateQueries({ queryKey: ['tasks'] }).

M6Docs summarize routes prose through the email extraction pipeline

summarizeMessage feeds the selection in as bodyHtml, so doc text passes through htmlToText (literal <TBD> style fragments vanish), then stripSignature (a lone -- line truncates the source), then a silent 3000-character clamp. A long selection is summarised from its first ~3000 characters with no indication. Preview-then-apply makes the result visible, but not the truncation.

M7The AI row appears to anonymous share-link viewers

On AI_LOCKED builds the store forces enabled: true for everyone, including visitors on /docs/share/[token]. If the link grants editing, the bubble shows Rewrite and Summarize; authedFetch then sends no Authorization header and the popover displays the raw 401 body. Not a security hole — the server refuses — but it offers a control that cannot work.

M8A quick-added task can vanish on the TODAY tab

The new task is prepended to tasks, but filteredByTab drops anything without a due date today. The toast says "Task added" while the list shows nothing new. Worth either switching the tab or noting it in the toast.

M9The preview popover doesn't follow its text

aiAnchor is a snapshot of the bubble's fixed coordinates. Scrolling during a long stream leaves the popover parked while the selection it describes moves away. Cosmetic, but noticeable on a slow model.

Build-script fragility

Notes for the ledger, not blockers. The recipe works today and is tar-verified; these are the ways it stops working later.

  1. It depends on prisma being a runtime dependency. ./node_modules/.bin/prisma only exists in a --prod bundle because prisma sits in dependencies (apps/api/package.json:48), not the conventional devDependencies. Any tidy-up that moves it breaks the bundle build — loudly, thanks to set -e, which is the good outcome. Worth a comment in package.json rather than only in the script.
  2. Nothing asserts the generated client made it in. The exact failure that caused the rollback would still only surface as a crash-loop on the VM. Add test -e node_modules/.prisma/client/default.js and a node -e "require('.prisma/client')" smoke inside the container, before tar.
  3. The schema copy is conditional and silent. [ -f /bundle/prisma/schema.prisma ] || cp -r … accepts whatever pnpm deploy happened to include. If the schema moves to a workspace package or a multi-file directory, the guard still passes and generate runs against whatever is there.
  4. Two generates can diverge. The workspace generate (for the nest build's typecheck) and the bundle generate read the schema by different paths. A Prisma major bump that changes the default output location would satisfy one and not the other.
  5. The tarball has no top-level directory. tar -czf … . from /bundle means the documented extract step must pre-create /tmp/api.new. Keep that in the deploy note; it is easy to lose.

Recommendations

  1. Before merge: clamp the docs apply range and move the summarize insert to the block boundary (I1, I2). Two small edits in one file, both in applyAi.
  2. First fast-follow: wire abort controllers into quick-add and the due-hint parse (I3), and gate the quick-add indicator on aiEnabled (M1). That completes the cross-cutting contract the spec set, so the four features honour the same five guardrails.
  3. Switch the parser to local date parts (M2). It is a two-line change and it is the only place in the change set where an off-by-one is invisible to the user until the task is already wrong.
  4. Consider a docs-specific summarize option rather than reusing the email extractor (M6) — at minimum surface the 3000-character clamp in the popover, so a long selection doesn't produce a confidently partial summary.
  5. Ledger the two prompt framings as intentional. The quick-add feeds raw user input; the commitments flow feeds {text} — due: {hint} and then discards the parsed title, using only the date. That asymmetry is deliberate and correct — a mangled title from the commitment framing can never reach the user — but it deserves a comment, because the next person to touch it will be tempted to "fix" it by using parsed.title.
