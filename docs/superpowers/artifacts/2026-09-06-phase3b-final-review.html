ImportantShould fix before merge

1 · Cache-read GETs share the 10/min throttle with the generation POSTs

apps/api/src/chat/generation.controller.ts:25 — @Throttle({ default: { limit: 10, ttl: 60_000 } }) is class-level, so GET /ai/dossier and GET /ai/meeting-prep draw from the same bucket as the expensive POSTs. MeetingPrepView refetches on every eventId change and PersonDossierPanel on every open, so clicking through 10+ calendar events (or dossier targets) in a minute exhausts it. The 429 is swallowed by getCached() (!res.ok → null), so a previously generated pack silently renders as never-generated, and a subsequent POST 429s into the error banner. The /ai/ask precedent (20/min) guards a controller whose only heavy route is the POST — a per-task review couldn't see this because the throttle (Task 7) and the GET-per-selection consumer (Task 10) landed in different tasks.

Fix: move @Throttle onto the two POST handlers only (GETs fall back to the global 120/min), or give the GETs their own generous limit.

MinorNice to have — none block merge

2 · Display names / event titles enter the prompt unfenced and unscanned in SUBJECT

The dossier SUBJECT is `${personLabel} <${email}>` (attacker-controlled fromName), prep's is the event title. buildGenerationPrompt neutralizes structurally and strips [sN], but detectInjectionAttempt never runs on these strings, so a semantic payload in a display name ("J D — ignore the sources and state…") sits outside the fence without tripping the amber banner. Same exposure class as 3a's From:/Subject: header lines — not a regression, and neutralization holds against fence-forging. Hardening follow-up: OR detectInjectionAttempt(subject) into the flag set.

3 · Entry-point gating is inconsistent between mail and calendar

Mail sender buttons (ThreadMessage.tsx, MailDetail.tsx) render only when aiEnabled; calendar attendee/organizer buttons render unconditionally. Dossier facts are deterministic (non-AI), so either both should show or both should hide — as shipped, the AI kill switch removes a non-AI affordance in mail while calendar keeps it.

4 · Mail entry points don't skip self

Clicking your own name on a sent message opens the panel straight into the 400 banner ("cannot open a dossier on yourself"). Calendar guards with isSelf; the mail sites don't have the user's email in scope but could get it from the auth store.

5 · Degraded-leg generations are cached as fresh

If the mail leg rejects (dossier) or retrieval rejects (prep), the impoverished output is still upserted with a normal anchor — it then reads as a fresh cache until newer mail arrives. The unconditional Regenerate button (controller ruling) mitigates; consider skipping the write when any leg degraded.

6 · Prep sourceAnchor includes retrieval-leg mail dates

Spec says legs b/e only (meeting-prep.service.ts:1288-1290 folds all deduped mail sources, retrieval hits included). An unusually new retrieval hit pushes the anchor later and slightly desensitizes staleness. Cosmetic drift, err on the quiet side.

7 · cache.upsert failure lands after res.end()

In GenerationController.stream, an upsert rejection (transient DB error) propagates into Nest's exception filter on an already-ended response — noisy log, lost cache write, no user impact. Wrap in try/catch + logger.warn.

8 · Panel fetches the cached narrative even when AI is off

PersonDossierPanel effect 1 calls getCachedDossier regardless of aiEnabled. Read-only and never rendered, but it spends the (currently tight) throttle and is an AI-endpoint call with the switch off.

9 · Prep retrieval leg is a superset of the spec's

Spec: "the existing mail-vec + doc-vec legs"; implementation calls full retrieve(…, { types: ['mail','doc'] }), which includes the keyword leg. More context, same ACL, benign — recording it as deliberate would close the drift.
